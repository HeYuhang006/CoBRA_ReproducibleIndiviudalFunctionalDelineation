# External inputs and author code

This repository intentionally excludes raw MRI, computed arrays/checkpoints/results, author distributions and binary atlas/template resources. Existing local copies are left untouched. Obtain access through the appropriate data/author channels; do not commit credentials or restricted inputs.

1. **HCP**: the configured HCP-YA and HCP-Retest roots contain ICA-FIX-cleaned MSMAll CIFTI time series, motion regressors and structural surfaces. Paths/cohort identities are in `configs/`; no image data are in those JSON files. Motion and vertex areas are recomputed from raw ancillary inputs. Task z-statistics are optional for the task stage. Data access: <https://www.humanconnectome.org/study/hcp-young-adult>.
2. **Templates/tools**: install TemplateFlow fsLR inputs, FreeSurfer fsaverage4 inputs needed by HFR18, Connectome Workbench and the Python dependencies. Set paths in `configs/project.json`. The original platform was Linux with CUDA; production MATLAB steps require a working MATLAB license. These executables are not bundled.
3. **GPIP**: obtain the author distribution from <https://neuroimageusc.github.io/GPIP>. Place its `gpip_share` directory at `GPIP/author/gpip_share` so the required files match `GPIP/source_manifest.json`. Preserve originals; `GPIP/compat` and `GPIP/05_individual/*.m` contain the explicit external adapters. Step2 checks runtime/source compatibility before fitting. The author distribution is deliberately ignored by Git.
4. **HFR18 / Wang-style**: author release <https://github.com/MeilingAva/Homologous-Functional-Regions>, pinned commit `6fe36e095198fbf317778b7b9f663f492fa5462f`. Restore it into `references/wang2015_author_hfr/HFR_ai` and restore its `resampling`, distance and `commit.json` inputs under `references/wang2015_author_hfr`, matching the original provenance/download manifests. The18-network implementation is the later public HFR release, not a claim of bitwise reproduction of Wang2015. The100-parcel variant is an adapted diagnostic.
5. **RNCut**: obtain the original distribution via <https://www.nitrc.org/projects/rncut>. The production extension uses `GPT_workplace/resources/rncut_author/RNCut/Code`; its original source and compatibility/probe records are described in `docs/provenance/production_baseline_sources`. Keep author P-code/core binaries outside Git. Surface adapter and initialization guards are separate, inspectable source files in `TraditionalMethod/experiments/group_nmf_rncut_20261009`.
6. **Atlas reference inputs**: restore the original Schaefer, Yeo, HFR and other selected atlas resources under `resources/atlases` and `references` using the filenames/hashes in `docs/provenance/external_input_manifest.json`. The production35-atlas benchmark needs its original resource registry. Missing inputs should fail explicitly; do not substitute new atlases or old output labels silently.

On the original4090 host, source resources can be copied (not moved) from the canonical `/dataspace/yuhang_data/IndividualFunctionalParcellation/CoBRA` installation into a separate checkout. Keep all copies ignored and verify hashes. Do not point `work_root` at that canonical source directory or any previous experiment result directory. The CPU audit and all dry-run plans work before these external inputs are installed; actual scientific stages require them.

No new license is assigned to third-party code by this upload. Check author/data reuse terms before redistributing their packages or making a public release.
